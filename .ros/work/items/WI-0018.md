# WI-0018: Storage migration, backup, schema evolution, and operational recovery

Status: captured  
Source authority: `input-documents/survey-engine-administrator-console-storage-analytics-visualization-requirements.txt`  
Migration ledger: `docs/requirements/survey-engine-requirements-migration.md`

## Objective

Ensure Signal datasets can survive provider changes, schema evolution, outages, corruption, restore operations, and eventual migration from GitHub to a service without changing meaning.

## Acceptance criteria

- [ ] Implement resumable/idempotent migration with source validation, immutable copy, derived rebuild/verification, semantic comparison, and explicit activation.
- [ ] Implement provider-independent backup/restore with dataset identity and hash validation before activation.
- [ ] Define compatible schema adapters and explicit unsupported-future-version behavior without silently changing canonical scores.
- [ ] Support read-only/degraded recovery paths with clear staleness evidence and no implied successful writes.
- [ ] Expose operational health and recovery diagnostics sufficient to plan and verify repair/migration work.
